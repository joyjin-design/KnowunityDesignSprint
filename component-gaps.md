# Component gaps

Things built inline during a screen build because Storybook had no component for them. When the same thing is needed on a second screen, it gets built as a real component instead, and both lines are marked `→ promoted to <Name>`. Items `SPEC.md` says to build inline stay inline.

- Knowie's speech bubble holding the question (surface fill, left-pointing tail), plus the flat shadow under the mascot — for 1 Verdict sheet — inline in app/screens/VerdictScreen.tsx. `SPEC.md` screen 10 says to build the bubble inline, not as a component, so it isn't promoted when the loop screen needs it. Second occurrence: 5 Mic-off sheet, inline again in app/screens/MicOffScreen.tsx (reconstructing the loop's Idle look behind the sheet) — still not promoted, same exception.
- Static XP chip "⚡2" (Phosphor Lightning and a label in `accent/blue/onSubtle`, no fill) — for 1 Verdict sheet — inline in app/screens/VerdictScreen.tsx. `Chip`'s colours (Primary, pro) don't cover it, and Figma draws it as a plain frame; whether it should be `Chip` is `SPEC.md` Open #8. Second occurrence: 5 Mic-off sheet, inline again in app/screens/MicOffScreen.tsx, same reasoning.
- Latency switch: a 3-way segmented control (Normal / Slow / Hang) for the facilitator's forced-latency override — for 2 Turn log — inline in app/screens/LogScreen.tsx. No toggle or segmented-control component exists in Storybook or design-system.md. Decided in sprint-context.md (2026-09-14) but not named as a component in `SPEC.md`'s screen 2 text.
- Turn log rows: session dividers and turn cards, tokens only, no data-table or list component in Storybook — for 2 Turn log — inline in app/screens/LogScreen.tsx. `SPEC.md` says "the rows use tokens only" for this screen, the same inline-by-design treatment as the summary's rows (screen 8) and the loop's speech bubble (screen 10); not to be promoted if a second screen needs rows, per that exception.
